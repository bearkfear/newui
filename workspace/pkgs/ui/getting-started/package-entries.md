# Package entries

[Getting started](README.md)

## Import components

newui remains one package. Each area provides named component and type exports. Installable artifacts are generated by `bun run build` from `workspace/`; the package remains private and unpublished.

| Entry                      | Public resources                                                                                |
| -------------------------- | ----------------------------------------------------------------------------------------------- |
| `@egcs/newui`              | All non-chart areas below, preserving the existing API                                          |
| `@egcs/newui/actions`      | Button, ButtonGroup, ContextMenu, DropdownMenu, Menubar                                         |
| `@egcs/newui/compositions` | ActionBar, Footer, Hero, MediaObject, Panel                                                     |
| `@egcs/newui/content`      | Accordion, Avatar, Badge, Card, Collapsible, Counter, Heading, Prose, Separator, Text, Timeline |
| `@egcs/newui/data`         | BadgeDelta, BarList, DeltaBar, native Table                                                     |
| `@egcs/newui/feedback`     | Callout, Empty, Loading, PageLoading, Progress, ProgressCircle, Toast, Toaster, createToaster   |
| `@egcs/newui/forms`        | Field, Input, InputGroup, Textarea                                                              |
| `@egcs/newui/layout`       | Container, Resizable, Section                                                                   |
| `@egcs/newui/navigation`   | Breadcrumb, Navbar, NavigationMenu, Pagination, Sidebar, Steps, Tabs, VerticalMenu              |
| `@egcs/newui/overlays`     | AlertDialog, Dialog, HoverCard, Popover, Sheet, Tooltip                                         |
| `@egcs/newui/charts`       | BarChart, DonutChart, LineChart and chart types                                                 |

```tsx
import { Button, type ButtonProps } from "@egcs/newui/actions";
import { Card } from "@egcs/newui/content";
import { Field, Input } from "@egcs/newui/forms";
import "@egcs/newui/styles.css";
```

All entries preserve their existing public types, including shared part types and portal aliases. Charts stay opt-in through `@egcs/newui/charts`; they are not re-exported from `@egcs/newui/data` or `@egcs/newui`. Foundations currently expose CSS contracts, and Utilities have no implemented public API, so neither has an empty JavaScript entry.

## Styles and themes

Import `@egcs/newui/styles.css` once in the application entry. It remains the complete compiled stylesheet, with global Preflight and `nui`-prefixed utilities. Area JavaScript imports do not select CSS or require a consumer Tailwind build.

System light/dark selection and `data-nui-theme` overrides remain available through the shared CSS. See [themes](../foundations/themes.md). Alternatively, use the [Tailwind consumer integration](tailwind.md): `@egcs/newui/postcss`, documented `@egcs/newui/tailwind/<area>.css` selections, and an optional `@egcs/newui/tailwind/preset.css` sharing tokens with application utilities. Compiler peers are optional when using the complete stylesheet.

## Build and module identity

The manifest exposes declaration files, JSX through the `solid` condition for the consumer's Solid compiler, and an ESM browser fallback through `import`. Browser fallback code is not an SSR target.

The build generates all entries together, preserves reachable implementation module boundaries through internal entries, and shares chunks within each condition. Main and area imports resolve to the same implementations and contexts when resolved under the same condition. Keep the generated internal files and chunks with the entry files; copying an entry alone is insufficient. JavaScript side-effect metadata continues to preserve CSS imports.

The [consumer bundle report](bundle-sizes.md) compares named main/area imports, dependency elimination, and mixed Button bindings in both conditions. SSR/hydration support and packed-package validation without workspace patches remain distribution follow-up work. Installing the package still installs all declared dependencies, including chart dependencies.
